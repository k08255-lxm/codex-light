# Safe first-install entrypoint

The normal (non-MigrationStage) Velopack build additionally produces `CodexLight-NewInstall-<version>-x64.zip`. Publish that ZIP as the user-facing new-install asset, not the raw internal vendor Setup. The ZIP includes the net48 GUI wrapper, its config/library, project MIT license, Chinese instructions and hashes. Windows 10/11 can run the wrapper before .NET 10 is installed. The existing vendor package and migration-stage path are preserved; MigrationStage deliberately does not create this first-install entrypoint.

The wrapper embeds the exact vendor Setup and its hash at build time, checks SHA256 before dependency changes and again before execution, and retains a read-only lease during vendor execution. It first reuses compatible installed Node 22.15+ x64 for the full DSH bridge (core alone supports Node 20+) and Codex CLI. Each missing dependency requires a separate explicit Yes (default No), uses the existing official pinned download service, and is re-detected after successful installation. Detection uncertainty, cancellation, errors and reboot-required results stop the chain. No silent Node installation, automatic account login, Codex config modification or system PATH modification.

It is intentionally **first-install only**: existing Codex Light program/data directories, registration, or running desktop mutex block it, even if remnants appear empty. This conservative rule can require manual inspection after an interrupted first install; it never deletes leftovers or uninstalls an old MSI to make progress. Migration keeps its separate safety process. The user's explicit start checkbox confirms tasks are ended; no task is killed. Fresh-install absence checks run again immediately before starting vendor Setup. The vendor receives only a fixed separate `CodexLightDesktop` install directory, no silent or restart override. Windows/organization/security blocks are reported without escalation or bypass.

The GUI exposes cancellation during supported downloads, does not force-kill official installers, and does not close while an installer is active. Successful vendor exit is reported as installer completion, not proof of real-account health. Dependencies can remain installed when a later step fails; there is no blind rollback of shared/system runtimes. Extracted vendor copies may remain for diagnosis.

Prerelease tool/runtime `1.3.39-g8d2844f` remains pinned and clearly disclosed. The application wrapper itself is unsigned; embedded-content hashes are not a publisher signature. The previous machine's vendor self-read `os error 5` is not claimed fixed by adding this wrapper. A separate clean-machine interactive test remains required.

Tests in `tests/` execute only an injected fake host. They cover both dependencies present, each independently missing, both missing, denied consent, uncertain detection, error/cancel/reboot, failed post-detection and vendor failure. They do not install anything, call models, open the GUI, or exercise UAC.


Build-only verification on the development machine: the combined wrapper and CLI service compiled with zero warnings/errors; 58 fake-host state assertions passed. A generated ZIP was checked for exact intended files and every listed SHA256. The wrapper embedded Setup resource was independently read and hashed without invoking the executable. The vendor used in that packaging smoke test predates private-CLI backend discovery, so that ZIP is not a deliverable. A fresh full application build after merging the CLI backend is mandatory. No interactive wrapper/UAC/vendor installation was run.


A detected Node 20.x / 22.0–22.14 is not treated as a fully compatible DSH bridge runtime. It takes a distinct upgrade-consent path: the dialog names the existing version, explains that the official MSI upgrades shared system Node and can affect other software, defaults to No, and permits exiting to prepare a separate compatible environment instead. The shared Node helper still describes the core 20+ requirement; this stricter complete-app gate is specific to the first-install wrapper. Existing Node24.13 is reused without installing anything.
