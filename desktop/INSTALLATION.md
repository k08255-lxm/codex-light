# Windows 安装与升级

从 GitHub Release 下载并打开 `CodexLight-Setup-<version>-x64.exe`（如 `CodexLight-Setup-0.4.1-x64.exe`）。这是内嵌 MSI 的单文件安装器，不需要旁边放 config/payload 目录。它使用系统 .NET Framework 4.8，应用使用 .NET 10 Windows Desktop Runtime；不需要安装 SDK。

只需使用上述版本化 EXE。它负责运行环境检查、安装与更新，并内置应用安装包。升级和卸载由 Windows Installer 管理；若使用 ZIP 发行包，请先完整解压。0.4.1 另保留同内容的 `CodexLight-Setup.exe`，供仅识别旧名称的 0.4.0 应用内更新使用；`SHA256SUMS.txt` 同时列出两个附件的精确文件名与哈希。

1. 打开后自动检查并复用已安装的兼容 .NET 10、WebView2、Node.js 20+。Node 从随附目录、标准安装目录、注册表和 PATH 发现，并实际检查版本。
2. 点击“安装”后，自动从官方来源下载缺少的依赖，校验哈希、签名及发布者，通过官方安装程序安装并重新检测；不绕过 UAC、证书或系统安全提示。进度与错误可在详情中查看。
3. 新安装使用默认位置，或点击“更改”选择父文件夹；无需预先创建CodexLight目录。
4. 已有本产品 MSI 安装会沿用原位置并按 MSI 规则升级。同一产品标识、同版本再次安装会刷新应用文件；同版本但不同标识的旧候选包须使用更高版本升级。若该安装位置的应用仍在运行（包括托盘），安装器会提示“关闭并继续”。保存工作并确认后，安装器请求应用正常退出；取消、退出失败或应用重新启动时不会继续安装。
5. 原先非MSI安装不自动认领或覆盖，须选择新的安装位置；项目、共享Codex配置和会话不会被迁移或删除。
6. 卸载入口为Windows设置中的已安装应用。卸载不删除项目、用户设置和共享运行时。

安装失败由Windows Installer处理事务回滚，Setup保留日志及所选路径。已经安装的共享依赖不会因应用安装失败而卸载。

本包是 framework-dependent，不默认携带整套 .NET。Windows x64 为当前目标。程序代码未做 Authenticode 签名。

应用内的“设置 → 关于”支持检查 GitHub 最新稳定版本，下载后核验发布的 SHA256；点击“打开安装程序”并确认后才启动安装向导。可以先退出应用，也可以在向导中确认关闭。检查、下载和安装都是显式操作，不会后台静默安装或降级。

主程序会自动选择可用的兼容 WebView2，初始化明确失败时尝试其他标准安装位置。系统安全弹窗分属防火墙、文件来源和应用信誉；本程序不会通过改防火墙、关闭 Defender、添加排除项或去掉来源标记来压制提示。正式发布可用 `desktop/sign-release.ps1` 和已有发布证书签名，签名本身也不保证新版本立即取得 SmartScreen 信誉。

## 验证边界

可用性取决于本机 Windows 权限、运行时和已有安装状态。构建时的包内容检查、模拟测试和编译成功不等同于每台电脑的实机兼容性验证。
